## 3. 你的首要任务：Docker 构建 + 容器内端到端（补 M3）

### 3.1 构建与启动
```bash
# 在仓库根目录
cp .env.example .env         # 可选，或用下面 export
export PASSWORD=changeme     # Web UI 登录口令（务必设置，否则开放无鉴权）
export API_TOKEN=            # 可空；设置后可第三方 X-API-Token 调用
export SESSION_SECRET=       # 建议设置一个随机串；空则取 PASSWORD
docker compose up -d --build
docker compose ps
```
- 前端： http://localhost:8088
- 后端： http://localhost:8080/api/v1/health

### 3.2 必做的冒烟（容器内真实链路）
```bash
# 健康
curl -s http://localhost:8080/api/v1/health
# 登录（拿 Cookie）
curl -s -c cookie.txt -X POST http://localhost:8080/api/v1/login -H 'Content-Type: application/json' -d '{"password":"changeme"}'
# 会话
curl -s -b cookie.txt http://localhost:8080/api/v1/session
# 空列表应为 []（不是 null，验证 B7 修复生效）
curl -s -b cookie.txt http://localhost:8080/api/v1/knowledge-bases
```
- 浏览器打开 http://localhost:8088 → 登录 → 建任务（可先不选方案，import/audio 会真实跑 ffmpeg）→ 看阶段/进度/结果。
- 重点验证：**nginx 反代 /api → backend:8080 正常、Cookie 登录在容器内生效、大文件上传（client_max_body_size=2048m）不报 413**。

### 3.3 已知需关注的 Docker 风险（静态审查结论，未实构验证过）
- **A1 无 healthcheck**：`depends_on` 仅控制启动顺序，backend 未就绪时前端可能短暂 502。建议给 backend 加 healthcheck，前端改 `depends_on: {backend: {condition: service_healthy}}`。
- **A2 前端 Dockerfile 用 `npm install` 且未 COPY package-lock.json**：建议改 `npm ci` 并锁定依赖，保证可复现。
- **A3/A4 基础镜像未钉 digest、容器以 root 运行**：建议钉 digest、加非 root 用户。
- **前端构建用 npmmirror 源**：如你机器网络不同，注意 registry 可达性。
- 后端多阶段：`golang:1.23-bookworm` 构建 + `debian:bookworm-slim` 运行（含 ffmpeg/ca-certificates），`CGO_ENABLED=0` 配纯 Go sqlite，预期可构建。
- 卷：`./data:/data`（SQLite 与任务产物落这里）；`TMP_DIR` 默认 `/tmp`，中间产物在容器内 /tmp，容器重建即丢（不影响已入库产物）。

> 若 `docker compose build` 报错：把**完整原始错误**贴出来，按报错修 Dockerfile，并更新本节与 `verify/M3/` 证据。

## 4. 真实 AI（ASR）补验（次要，拿得到 Key 再做）

原环境缺真实 ASR 通道，B1 的 ASR 阶段是**降级**（本地 SRT 作 fused 输入）；summary/knowledge/fused 由真实 openai_chat 模型真实生成。

补验方式：在 Web UI 的「配置方案」里，为 `asr` 能力建一个指向**真实可用 ASR 端点**的方案：
- `deepseek_asr`：POST `{base_url}/v1/tools/asr`（multipart file）——需提供真能用的 base_url + api_key + model。
- `openai_audio`：POST `{base_url}/v1/audio/transcriptions`（Whisper 类）。
- chat/vision/reading 用 `openai_chat / openai_responses / anthropic_messages / gemini` 任一真实可用的。
建任务时选好 asr 方案 + 勾选「通过 ASR 生成 AI 字幕」，跑 1 个短视频，确认 `asr.srt` 非空、`fused.srt` 含 ASR 内容、`summary.md/knowledge.md` 正常。

## 7. 协作约定（若继续多 Agent 开发）

沿用 `docs/AGENTS.md` 与 `plan.md` 的分工与纪律：
- **Lead** 只调度/裁定/汇总，不写业务代码。
- **Backend** 只改 `backend/`；**Frontend** 只改 `frontend/`；**Verification** 只读 + 写 `verify/`。
- 每个 Agent 用**独立 worktree**（避免共用工作目录切分支互相覆盖，本项目历史上发生过一次）。示例：`git worktree add ../be_wt feat/backend-xxx`。
- 分支：`feat/backend-*` / `feat/frontend-*` off `dev`，完成合并 `dev` 后推 `dev`；**不碰 main、不强推**。
- **证据至上**：任何"完成"必须附命令+原始输出+产物路径；Verification 独立复跑，不采信自述；无证据视为未完成。
- 提交用简体中文 Conventional Commits。
